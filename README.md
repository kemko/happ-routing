# Happ / Mihomo routing

Общая политика для Happ и Mihomo, в том числе XKeen: выбранные сервисы и списки блокировок идут через VPN, остальное — напрямую.
Источники задаются в `sources.json`, категории и ручные исключения — в `happ-routing.json`. Одна сборка скачивает и проверяет списки, затем из одних данных создаёт геобазы Happ и четыре набора MRS для Mihomo.

## Подключение Happ

1. Откройте [ссылку импорта](https://raw.githubusercontent.com/kemko/happ-routing/release/happ-import-link.txt), скопируйте её и импортируйте в Happ как профиль маршрутизации.
2. Выберите профиль у нужной подписки, дождитесь загрузки геофайлов и переподключитесь.

Либо вставьте [готовый JSON](https://raw.githubusercontent.com/kemko/happ-routing/release/happ-routing.json) в [редактор Happ](https://routing.happ.su/ru) и импортируйте полученную ссылку.

Постоянные адреса баз:

```text
https://raw.githubusercontent.com/kemko/happ-routing/release/geosite.dat
https://raw.githubusercontent.com/kemko/happ-routing/release/geoip.dat
```

При переходе со старого профиля один раз импортируйте новый и переподключитесь. В нём используются постоянные ссылки `geosite:routing-direct`, `geosite:routing-proxy`, `geoip:routing-direct`, `geoip:routing-proxy`. Ручные домены и выбранные категории разворачиваются внутрь этих наборов при сборке: после изменения их состава достаточно обновления геобаз, повторный импорт профиля не нужен. Настройки DNS и другие параметры самого профиля таким способом не обновляются.

## Подключение Mihomo / XKeen

В существующем конфиге замените целиком блоки `rule-providers` и `rules` содержимым [mihomo-rules.yaml](mihomo-rules.yaml). Готовая копия публикуется и в [release](https://raw.githubusercontent.com/kemko/happ-routing/release/mihomo-rules.yaml). Сохраните локальные `proxies`, группу `Proxy`, DNS, порты и настройки XKeen. Учётные данные серверов не входят в общий экспорт.

Проверьте итоговый конфиг через `mihomo -t` с фактическими путями вашей установки, затем перезапустите XKeen обычным способом. Подключайте новые URL после публикации первой сборки с MRS.

Провайдеры обновляются раз в час (`interval: 3600`). Сначала проверяются прямые доменные исключения, затем домены VPN, затем прямые и проксируемые IP. Если ни одно правило не совпало, используется `DIRECT`. Параметра `no-resolve` нет: после доменных правил Mihomo может разрешить имя для проверки IP, что соответствует выбранному принципу Happ `IPIfNonMatch`.

Скачивание правил идёт через группу `Proxy`, чтобы блокировка GitHub у провайдера не мешала обновлениям. Группа должна работать независимо от этих правил; первый запуск требует доступного VPN. Политика общая, но DNS-ответы и время обновления на разных устройствах могут различаться.

| Набор | Happ | Mihomo |
| --- | --- | --- |
| Прямые домены | `geosite:routing-direct` | `mihomo/direct-domains.mrs` |
| Домены VPN | `geosite:routing-proxy` | `mihomo/proxy-domains.mrs` |
| Прямые IP | `geoip:routing-direct` | `mihomo/direct-ips.mrs` |
| IP VPN | `geoip:routing-proxy` | `mihomo/proxy-ips.mrs` |

## Состав

| Категории GeoSite | Источник |
| --- | --- |
| `ai`, `ai-cn`, `gemini`, `youtube`, `twitter`, `tiktok`, `telegram`, `cloudflare`, `kinopub`, `private` | Соответствующие категории MetaCubeX |
| `rkn-domains` | RussiaFancyLists: `blacklist/domains/full-sld.lst` |
| `foreign-geoblock` | RussiaFancyLists: `geoblock/full-sld.lst` |

| Категории GeoIP | Источник |
| --- | --- |
| `twitter`, `telegram`, `cloudflare`, `private` | Соответствующие категории MetaCubeX |
| `rkn-ip` | RussiaFancyLists: `blacklist/ipsets/full.lst` |

AI используется целиком, включая китайские сервисы. Все конкретные URL находятся в [sources.json](sources.json).

В исходном [happ-routing.json](https://github.com/kemko/happ-routing/blob/main/happ-routing.json) сохранены ручные исключения:

- `DirectSites`: `alib.ru` и приватные домены.
- `ProxySites`: категории и объединённые ручные домены из Happ и XKeen, включая отдельное прежнее правило `gvt1.com`.
- `DirectIp`: приватные адреса.
- `ProxyIp`: категории Twitter, Telegram, Cloudflare и РКН.

`domain:example.com` включает сам домен и поддомены; `full:example.com` — только точное имя. Старые исходные категории в геобазах сохраняются для совместимости, поэтому старые профили работают, но не получают новую общую политику до повторного импорта.

Поддерживается согласованный режим: `GlobalProxy: "false"`, `RouteOrder: "direct-proxy-block"`, `DomainStrategy: "IPIfNonMatch"`, пустые блокирующие списки и четыре непустых итоговых набора. Неизвестные категории, неподдерживаемые правила или изменение этого режима останавливают сборку, чтобы экспорты не расходились. Блокировка рекламы не включена.

## Обновление

GitHub Actions ежедневно в 03:17 UTC (06:17 по Москве) скачивает все списки заново, проверяет их, собирает базы и публикует результат в ветку `release`. Также есть ручной запуск **Actions → Update geodata → Run workflow**. Изменения источников, профиля и сборщика запускают сборку автоматически.

В `main` хранится код. В `release` каждая изменившаяся сборка добавляется обычным коммитом: история файлов сохраняется, изменения можно сравнивать между коммитами. История начинается с текущего состояния ветки; ранее перезаписанные сборки автоматически не восстанавливаются. Не редактируйте её вручную. При ошибке загрузки или разбора публикация не выполняется и предыдущая сборка остаётся доступной.

Домены с DNS-меткой длиннее 63 байт или полным именем длиннее 253 байт пропускаются с предупреждением в логе: такие имена не могут использоваться в DNS. Остальные ошибки формата и списки без допустимых записей останавливают сборку.

Каждая сборка публикует исходные скачанные списки в `sources/`, снимок общей политики в `routing-policy.json`, их URL, количество записей и SHA-256 входных списков в `manifest.json`, а также контрольные суммы готовых файлов в `SHA256SUMS`. Текстовые наборы `mihomo/*.txt` содержат те же записи, что и итоговые категории геобаз; MRS создаются официальной командой `mihomo convert-ruleset`. Версия и SHA-256 конвертера закреплены в workflow.

Частота сборки и частота обновления в Happ различаются: согласно [документации Happ](https://github.com/HappDev/happ_su/blob/main/dev-docs/routing.md), клиент ограничивает обновление геофайлов. CI не меняет настройки уже установленного приложения.

Полный список РКН может сделать GeoSite большим. Списки `full-sld` используются как предоставлены источником: если в них попадает широкий доменный суффикс, он тоже пойдёт через VPN. Ручные прямые исключения имеют приоритет.

## Локальная сборка

Нужны Go версии из `go.mod`, Python 3 и `mihomo` в `PATH` (CI использует v1.19.33). В каталоге репозитория:

```sh
go test ./...
python3 -m unittest discover -s scripts
go run .
python3 scripts/profile.py
bash scripts/mihomo.sh
```

Результат появится в `dist/`. Для изменения политики редактируйте только `happ-routing.json`, для изменения источников — только `sources.json`. Сгенерированные файлы и правила на клиентах вручную не синхронизируются. В CI также проверяются преобразование MRS туда и обратно, готовый фрагмент Mihomo с локальными наборами и контрольные суммы.
